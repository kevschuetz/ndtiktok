<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator/LLM text → checker | Arbitrary text (later: LLM-generated scripts and claims, scraped captions) is matched against rules |
| config YAML → engine | Rule files are parsed at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | Override bypass of a block rule | mitigate | record_override raises for tier block (test); CLI exits 1 on such attempts |
| T-02-02 | Repudiation | Silent warn overrides | mitigate | check_override stores reason (CHECK length ≥5), rule_id, level, terminology_version, created_at, bound to text_sha256 so an edited text needs new overrides |
| T-02-03 | Tampering | YAML parsing | mitigate | yaml.safe_load + pydantic models rejecting unknown keys |
| T-02-04 | Denial of service | Catastrophic regex backtracking on long scripts | mitigate | Rules use simple anchored patterns without nested quantifiers; test runs a 10k-character input under 1 s |
| T-02-05 | Information disclosure / safety | Paraphrased blacklisted subject slips past keyword rules | accept | Deterministic hard gate now; Phase 2 adds an LLM flag-only second opinion and the operator review gate (research recommendation) |
</threat_model>
